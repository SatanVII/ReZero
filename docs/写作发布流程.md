# 写作发布流程（从创建到归档的完整操作手册）

> 适用项目：ReZero（Rezero-astro）｜ 更新：2026-09-19
> 全流程依赖两个 GitHub 仓库：**SatanVII/ReZero**（博客主仓）与 **SatanVII/blog-content**（内容子模块，文章存放处）。
> 内容推送后由 GitHub Actions 自动同步至主仓并触发 Vercel 部署，**全程无需手动干预部署**。

---

## 〇、全流程总览

```
①创建文章 → ②撰写内容 → ③本地预览 → ④格式校对 → ⑤提交并推送内容仓库
                                                      ↓（自动）
                              GitHub Actions 推进子模块指针 → Vercel 自动重建 → 线上生效
                                                      ↓
                                            ⑥归档与本地收尾
```

- ①~④ 全部发生在一处：`Rezero-astro/content/blog-post/<年份>/` 目录（内容子模块内）。
- ⑤ 推送内容仓库后，**自动化接管**（实测秒级~30 秒内完成指针推进与部署）。
- 依赖关系：② 依赖 ① 的 frontmatter（title 决定 URL）；③④ 依赖 ①② 的文件落盘；⑤ 是唯一「上线」动作；⑥ 是收尾习惯，不阻塞任何环节。

---

## 一、阶段①：创建文章

### 1.1 目录与文件约定

- 新文章放入 `content/blog-post/<年份>/<文件名>.md`（按年份子目录归档，如 `2026/`）。
- 文件名建议与标题一致（拼音或英文），**因为文章 URL 由 frontmatter 的 `title` 决定，与文件名无关**。

### 1.2 frontmatter 模板（必填字段一个都不能少）

```markdown
---
title: 文章标题
date: 2026-09-19
category: 日志
tags:
  - 标签一
  - 标签二
description: 一句话摘要（可选，但强烈建议写）
---

正文从这里有开始……
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | **决定文章 URL**（`/posts/<title>`）；全站不可重复 |
| `date` | ✅ | 日期（`YYYY-MM-DD`）；列表按它倒序排列 |
| `category` | ✅ | 分类：**日志 / 随笔** 会出现在「文章」列表；**灵感** 进火花流；**关于** 是自述页 |
| `tags` | ✅ | 数组格式（`- 标签` 每行一个） |
| `description` | 可选 | 列表/SEO 摘要；不写则自动截取正文 |

### 1.3 注意事项

- ⚠️ **标题全站唯一**：URL 以 title 生成，两篇文章同名会互相冲突。
- ⚠️ **分类名必须与现有集合精确一致**（`日志`/`随笔`/`灵感`/`关于`）：写错分类的文章不会出现在任何列表页。
- 「关于」分类仅一篇（自述页内容），日常写作不要使用；「灵感」分类有独立的小节拆分规则（按 `##` 标题拆分），非火花体内容请勿使用。

## 二、阶段②：撰写内容

### 2.1 本地预览（边写边看）

```bash
cd Rezero-astro
npm run dev        # 启动本地开发服务器（4321 端口，会自动同步内容与图片）
```

- 浏览器打开 `http://localhost:4321/posts/<标题>` 实时预览；保存文件自动热更新。
- `npm run dev` 启动前的 `predev` 会自动拉取内容仓库并同步图片，无需手动操作。

### 2.2 图片规范

- 文章图片放入 `content/IMAGES/`，正文中以 `/IMAGES/<文件名>` 引用：

  ```markdown
  ![图片描述](/IMAGES/xxx.jpg)
  ```

- 构建期自动拷贝到 `public/IMAGES/`，**不要**直接把图片放进 `public/`。
- 图片先压缩再入库（单张建议 ≤300KB），过大图会拖慢移动端首屏。

### 2.3 代码块与格式

- 代码块标注语言（\`\`\`ts、\`\`\`bash），站点有高亮与横向滚动样式。
- 长代码行、长 URL 在移动端已由样式兜底（代码块内部横向滚动、正文自动换行），无需特殊处理。

## 三、阶段③：格式校对（发布前检查清单）

```bash
npm run check      # 类型与语法检查（应输出 0 errors）
npm run build      # 完整构建演练（能 build 成功 = 线上大概率正常）
```

校对清单：

- [ ] frontmatter 五个字段齐全、分类拼写正确
- [ ] 标题全站唯一（在 `content/blog-post/` 全目录搜索确认）
- [ ] 图片路径以 `/IMAGES/` 开头且文件已放入 `content/IMAGES/`
- [ ] 代码块语言标注完整、无半截围栏
- [ ] 移动端预览正常（`npm run dev` 后用浏览器开发者工具切手机视口）

## 四、阶段④：提交并推送（上线动作）

```bash
cd content
git add blog-post/<年份>/<文件名>.md IMAGES/   # 添加新文章与图片
git commit -m "add article: <标题>"
git push origin main
```

推送后自动链路（无需任何手动操作）：

```
blog-content 收到 push
  → 自动通知 ReZero（repository_dispatch）
  → ReZero 自动推进子模块指针并 push
  → Vercel 自动重建（约 1~2 分钟）→ 文章上线
```

- 可在两个仓库的 **Actions** 页查看运行状态（blog-content 的 `Notify blog repo` 与 ReZero 的 `Content dispatch`）。
- 想立即确认：直接访问 `https://rezero-five.vercel.app/posts/<标题>`。

---

## 五、阶段⑤：归档与本地收尾

1. **文章归档即已完成**：内容仓库的提交历史就是完整档案（含每次修改）。
2. **本地主仓收尾**（自动链路推完指针后，本地主仓会落后一拍）：

   ```bash
   git pull        # 同步自动化推进的子模块指针提交
   ```

3. **一致性体检**（可选，随时可跑）：

   ```bash
   node tools/check-residue.mjs    # exit 0 = 主仓/内容仓/磁盘三者一致
   ```

## 六、常见问题与排错

| 症状 | 原因 | 处理 |
|---|---|---|
| 文章不显示在列表 | `category` 拼写错误（写了列表排除的分类，或错别字） | 核对 frontmatter 的 `category` 是否为 日志/随笔/灵感/关于 之一 |
| 构建报「title 重复」或路由异常 | 两篇文章 title 相同 | 改掉其中一篇的 title（URL 会随之变化） |
| 图片 404 | 图片未放入 `content/IMAGES/`，或引用路径没以 `/IMAGES/` 开头 | 核对路径后重新构建 |
| 推送被拒（non-fast-forward） | 远端有新提交（如自动化推进过指针） | `git pull --rebase` 后重推 |
| 推送内容后 30 分钟未上线 | 自动同步工作流可能未运行 | 查两仓库 Actions 页；可手动运行 ReZero 的 `Content dispatch` 工作流 |
| 本地 `npm run dev` 报 content 缺失 | content 子模块未就位 | `git submodule update --init` 后重试 |
| 字体/样式异常 | CSS 变更后缓存未失效 | 相关版本号参数已自动化，正常重部署即可；顽固时强刷（Ctrl+F5） |

## 七、命令速查

```bash
# —— 日常写作 ——
npm run dev                       # 本地预览（自动同步内容）
npm run check                     # 语法/类型校验
npm run build                     # 构建演练

# —— 发布 ——
cd content
git add blog-post/<年份>/ IMAGES/
git commit -m "add article: <标题>"
git push origin main              # 推送后自动部署

# —— 收尾与体检 ——
git pull                          # 主仓同步自动化指针
node tools/check-residue.mjs      # 三方一致性体检

# —— 紧急恢复 ——
git checkout -- .                 # 工作树文件丢失/被改坏时按 HEAD 恢复
```
